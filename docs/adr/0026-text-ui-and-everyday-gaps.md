# ADR-0026 暫定テキストUI（判断ログ可視化）＋普段使いの漏れ修正

- 状態: 採用（2026-06-11）。音声入力(Step2)が使えない場面（大学など）の暫定運用＋総当たりテストで出た漏れの修正。

## 課題
1. 音声入力がまだで、かつ声を出せない環境（大学等）でも操作・検証したい。
2. 普段使いの総当たりテスト（dry-run, scripts/scenario_test.py）で実害のある漏れが出た:
   - 「閉じて」に対応するツールが無く、近い名前の `モニタ消す`(画面スリープ) を誤爆。
   - ミュート未登録で「音消して」が `音量下げる(25%)` に化け、消えてないのに「完了」と言う。
   - モデルに渡す操作メニュー(`available_operations`)が新ツールを案内せず「天気=web_search」と古いまま。
   - 危険コマンド(再起動等)が `input()` 確認のため、Web等の非対話環境ではサーバを固める。

## 判断
- **Web UI を“音声の代わり”の暫定操作UI兼テスト台にする**（GUIレス方針[#6]への違反ではなく、開発・検証用の一時UI）。
  - テキスト入力 → 返答（吹き出し）→ **その下に「🧠判断・⚙動作・結果」のログ**を表示。
  - **ドライ/実行トグル**（ON=判断だけ / OFF=実際に実行）。読み上げトグル（[ADR-0024]）も併設。
- **close_app ツールを追加**：「閉じて/消して/やめて」を正しく受ける。サイトはタブを閉じ、アプリは quit。
- **config に ミュート/ミュート解除 を追加**。
- **操作メニューを現行10ツールに同期**（天気=get_weather を明記）。
- **危険コマンドは非対話環境では実行せず確認を促す**（`sys.stdin.isatty()` で判定。サーバを固めない・誤実行も防ぐ）。
- **実行後にモデルが無言なら、ツール結果を返答に流用**（空の「（…）」を防ぐ）。

## 検証（2026-06-11・再テスト）
- 「やっぱ閉じて」→ close_app(YouTube)（誤爆解消）、「音消して」→ run_system(ミュート)、天気→get_weather を維持。
- 既存18ケースは回帰なし。dry/実行の両経路を curl でE2E確認。
