# ADR-0033 実測コストメーター＋キャッシュ実効閾値の発見（月500円運用）

- 状態: 採用（2026-06-11）。[ADR-0032] の第2弾。目標「いっぱい使っても月500円未満・できるだけ安く」。

## 課題
1. ADR-0032 の persona 削減で、キャッシュ対象プレフィックス（tools+安定system）が **Haiku の最小キャッシュ
   要件を下回り、キャッシュが無言で無効化**していた（cw=0/cr=0、毎コール約4,400トークンをフル課金）。
2. `_rephrase` と MAX_TOOL_ROUNDS 超過時の最終コールが **tools 無しで呼んでいた** → tools はプロンプト先頭に
   描画されるため prefix が変わり、これもキャッシュmiss。
3. 実コストを観測する手段がなく「月いくらか」を確認できない。

## 発見（実測・重要）
**キャッシュ判定の内部トークン数は count_tokens の読みより常に 324 少ない**（パディング実験3点で完全一致:
count 4569→write 4245 / 4757→4433 / 5006→4682）。文書上の最小4096は内部値基準。
→ **count_tokens 読みで約4,420以上（安全には4,550以上）必要**。4,380では弾かれた。

## 判断
1. **安定部に実用ガイダンスを増量して閾値超え**（パディングではなく製品価値のある内容）:
   多段実行例・曖昧メディアの聞き返し・天気の要約様式・危険操作の確認・「何ができるの」ツアー・
   **ただいま/おやすみ/いってきます の振る舞い**・トーン調整（小言はひとさじ・努力報告には先に褒める）・
   TTS前提で箇条書き禁止。→ prefix= count 4,582（内部≈4,258）でキャッシュ稼働。
2. **キャッシュmiss修正**: `_rephrase` と最終フォールバックに tools＋`tool_choice:{type:"none"}` を付与
   （tool_choice の変更は tools+system キャッシュを壊さない）。
3. **実測コストメーター**: core.run_turn が全API呼び出し（ループ＋ガード＋言い換え）の usage を合算し
   円換算（単価 $/MTok: in 1.00 / out 5.00 / cache write 1.25 / read 0.10、JPY_PER_USD env・既定155）。
   web.py が costs.jsonl に記録し、**今ターン/今日/今月/月ペースをUIヘッダーに常時表示、
   ペース500円超で赤**。

## 結果（実測）
- ターン単価: 会話 **¥0.22〜0.27** / ツール実行 **¥0.52〜0.59** / バースト開始（キャッシュwrite）+約¥0.7。
- 月額試算: ライト(5T/日)≈**¥95** / 普通(15T/日)≈**¥220** / ヘビー(30T/日)≈**¥450** ✓ / 極端(40T/日)≈¥560(メーター赤で可視)。
- 挙動回帰なし（ただいま=天気×予定の先回りという良い副産物あり）。
