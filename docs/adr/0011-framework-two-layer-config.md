# ADR-0011 フレームワーク化：config 2層（auto / user）

- 状態: 採用（2026-06-11）

## 課題
身近な人に渡せるフレームワークにしたい。だが各自のアプリ・URL を手で全部書くのは重い。一方で完全自動も不可能（URL や独自システムコマンドは OS スキャンでは取得できない）。

## 選択肢
- A. 単一 config を手編集（現状）
- B. 自動生成のみ
- C. 自動層＋手動層の 2 分割

## 判断
**C**。
- `config.auto.json` … OS スキャンで生成、再生成可（アプリ一覧・自動分類・呼び名）
- `config.user.json` … 手動。URL・独自コマンド・自動分類の修正・追加の呼び名。**こちらが優先**
- 実行時に 2 層をマージし、user が auto を上書き

## 理由
- 自動で 9 割埋め、手動は最小（URL 等）に絞れる。
- **再スキャンしても手動編集が消えない**（auto だけ作り直す）。
- 配布時は「スキャン → 数項目埋める」で動く状態にできる。

## 影響
- `tools.load_config()` を 2 層マージ読みに変更。
- セットアップスクリプト（スキャン＋分類）を新設。
- 既存 `config_mac.json` / `config_win.json` は auto 層の初期値へ移行。
- 自動／手動の境界：**アプリ＝自動／URL・システムコマンド＝手動必須**。
