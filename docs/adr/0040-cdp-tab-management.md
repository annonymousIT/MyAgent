# ADR-0040 Chrome タブ単位の管理（CDP）＋ ウィンドウ/モニタ把握の常時注入

- 状態: 採用（2026-06-12）。④⑦の実装。

## 課題
- 「説明のために開いたタブは説明が終わったら閉じる」（ephemeral）が Windows では実装ゼロだった
  （close_browser_tabs は Mac の AppleScript のみ）。タブ単位の操作も不可。
- 「どの画面に何が開いているか」を LLM が知らないため、「整理して」「右のやつ左へ」等に対応できない。

## 判断
### タブ管理（CDP・cdp.py）
- Chrome DevTools Protocol（`--remote-debugging-port=9222`）の HTTP API でタブの列挙・作成・
  クローズ・タイトル検索クローズ。標準ライブラリのみ・短いタイムアウト・失敗しても本体を止めない。
- **壊さない移行戦略**（`tools._open_in_browser`）: ①CDP 生きてる→CDP でタブを開く（後で確実に閉じられる）
  ②Chrome 未起動→フラグ付きで起動（次回からタブ管理可能）③フラグ無し Chrome が既にいる→従来どおり
  既定ブラウザ（後片付け不可＝正直に劣化）。使い心地・見た目は変わらない。
- close_app は ⓪CDPタブ → ①ウィンドウ(WM_CLOSE) → ②taskkill の順で試す。ブラウザ本体の巻き込み防止は維持。

### ウィンドウ/モニタ把握（⑦）
- `win_ops.windows_overview()` が可視ウィンドウを「モニタ番号（左から1）×短縮タイトル」で列挙し、
  毎ターン `[Windows now]: mon1: …｜mon2: …` として注入。「整理して/並べ直して」は LLM が
  この材料から自分でレイアウトを決め、manage_window を複数回呼んで実現する。

### コスト相殺（②）
- 揮発ブロックに混ざっていた**静的な英語説明文をキャッシュ側（static_menu）へ移動**、日付マップを3週→2週に。
  → 揮発 368→311tok/ターン（**ウィンドウ一覧を足してなお減**）。ツール定義も -144tok（manage_window/add_schedule圧縮）。
