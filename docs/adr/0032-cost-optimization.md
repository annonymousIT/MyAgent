# ADR-0032 コスト最適化（月数百円を目標）— 英語化＋圧縮＋プロンプトキャッシュ

- 状態: 採用（2026-06-11）。ユーザー要望「月数百円に抑える」。Claude(haiku)継続。

## 課題
1リクエストの入力が **13,288トークン**もあった（実測）。内訳: tools(13定義)=8,013 / system=5,264。
複数ラウンドループ＋ガードで1ターン2〜5コール → 集中利用日に高額化。原因はモデルでもAPI浪費でもなく、
**プロンプト肥大＋キャッシュ未実装**。

## 判断（性能を落とさず構造でコストを下げる）
1. **内部プロンプトを英語化**（日本語は1字1〜2トークン、英語は約4字1トークン＝1/6〜1/8）。
   ツール定義の説明・[Hard rules]・[Capabilities]メニュー・context_textのラベルを英語に。
   **ユーザーへの返答は日本語＋人格を維持**（_RULESに「Always reply in Japanese, in character」明記）。
   人格(persona)の声・お手本・データ値（茨木/塾/曜日/config キー）は日本語のまま。
2. **詰め＋重複削除**: ツール説明を最小化（使い所は人格/メニューに集約）。launch_app候補は名前のみ列挙
   （エイリアスは実行時リゾルバが解決するので不要）。personaの[ふるまいの原則]はstatic_menuと重複→削除。
3. **プロンプトキャッシュ**: system を2ブロックに分割。安定ブロック（[Hard rules]＋persona＋static_menu）に
   cache_control を付け、tools も一緒にキャッシュ（描画順 tools→system）。変動ブロック（現在時刻・プロフィール・
   起動中アプリ）は境界の後ろ＝毎回フル。連続ターン・複数ラウンドループで安定部を **0.1倍** で再利用。
4. 履歴 MAX_HISTORY 10→6。

## 結果（実測）
- 入力トークン **13,288 → 4,420（−67%）**。うち約3,950がキャッシュ対象（ヒット時0.1倍）、変動部わずか約470。
- キャッシュ稼働確認: 2回目で安定ブロックを cache_read（write→read）。
- **性能影響なし**: 英語プロンプトでも 日本語・ツンデレ人格・正しいツール選択・「来週の月曜→6/15」日付解決・
  捏造ガード・聞き返し・ツール結果の人格言い換え すべて保持を実機確認。
- 試算: 通常のバースト利用で **月 ¥300〜600 レンジ**（従来比 約1/10）。

## 残メモ
- haikuのキャッシュ最小プレフィックスは4096トークン。安定ブロックは約4K弱でギリ機能（これ以上削るとキャッシュが効かない領域）。
- 散発的な単発利用（5分以上間隔）はキャッシュ期限切れで write 課金になるが、トークン自体が67%減なので影響小。
