# ADR-0029 永続パーソナル記憶＋簡易スケジュール（記憶×ライブ情報の融合）

- 状態: 採用（2026-06-11）。「なんでもやってくれるPCパートナー」化の第一歩——予定や個人情報を覚えていて、天気などのライブ情報と融合して気遣う相棒にする。

## 課題
会話記憶（直近Nターン・Step5(a)）はあるが**プロセスを落とすと消える短期記憶のみ**で、
「明日の予定なんだっけ？」「大学（＝茨木）明日雨大丈夫かな」「○○覚えておいて」が成立しなかった。
さらに LLM は今日の日付を知らないため、「明日」の解決を任せると日付を捏造する危険があった。

## 判断
1. **永続プロファイル = `profile.json`（ローカルJSON・1ファイル）**。構造は
   `user`（名前/呼び方）＋ `facts`（自由記述の事実の配列）＋ `places`（場所語→地名の解決表）＋
   `default_location`（既定地名）＋ `schedule`（`weekly`=毎週繰り返し / `dated`=日付指定）。
   構造化しすぎない：定型は構造化フィールド、それ以外は facts の自由記述で受ける（穴を減らす）。
   - **個人情報なので `.gitignore` 行きでコミットしない**。雛形 `profile.example.json` をコミット。
2. **データ層は新モジュール `profile_store.py`**（stdlib の `profile` と名前衝突しないよう store 付き）。
   読み書き・予定の実日付展開・注入文生成を担う。tools.py / core.py はこれを呼ぶだけ。
3. **日付計算は全部 Python 側**。`context_text()` が現在日時（日付・曜日・時刻）を毎ターン
   システムプロンプトに注入し、weekly 予定も Python が実日付（今日から7日）に展開して渡す。
   LLM は「明日」を注入された現在日時と展開済み予定から読むだけ＝**日付の計算・捏造をさせない**。
4. **注入は `core.build_system_prompt` = persona ＋ `profile_store.context_text()` ＋ available_operations()**。
   注入文には「これが記憶の全て。無いことは作らない。知らなければ正直に聞く」を明記（捏造防止の延長）。
   トークン節約のため予定は直近7日のみ・facts は一行連結。
5. **記憶ツール3つを追加**: `remember(fact)`（自由記述の永続記憶）/
   `add_schedule(title, weekday|date, time)`（毎週 or 日付指定。相対表現は LLM が注入済みの現在日時から
   絶対日付に直して渡す）/ `forget(query)`（部分一致で事実・予定を削除、何を消したか返す）。
6. **天気の強化（融合の要）**: `get_weather` を wttr.in `format=j1`(JSON) に変更し、
   **現在＋3日先まで（3時間毎・気温・降水確率）**のコンパクト要約を返す。「明日雨大丈夫？」に実データで
   答えられる。JSON が取れない時は従来の1行（現在のみ）にフォールバック。
   `location` を省略可にし、空ならプロファイルの `default_location`。「大学」等の場所語は
   LLM が注入済みの `places` 解決表で地名（茨木）に直して渡す（ツール定義と persona に明記）。
7. **persona 全面改善**: 「記憶と気遣い」節を新設——記憶を自然に織り込む・記憶×ライブ情報の融合・
   予定への一言ツッコミ（「勉強したんですか？^^;」）・記憶に無いことは正直に「記憶にない」。
   既存の丁寧敬語・1〜2文・あきれ＆気遣い・捏造防止・ウィンドウ/起動把握の原則は維持。
8. **Google カレンダー連携（#9）は今回見送り**。OAuth・トークン管理が重く、まずローカル簡易版で
   会話体験を確立する。`schedule` の構造は「外部カレンダー由来の dated イベントを流し込む」拡張に
   そのまま使える（同期モジュールを足すだけ）。リマインド（能動通知）も常駐が要るため別トラック（#7/#8）。

## 影響
- 新規: `profile_store.py`（データ層）、`profile.example.json`（雛形）、`profile.json`（ローカルのみ・gitignore）。
- tools.py: `remember`/`add_schedule`/`forget` 追加（TOOL_DEFS/DISPATCH 登録）、`get_weather` 予報化＋既定地。
- core.py: `build_system_prompt` に `context_text()` 注入、操作一覧に記憶ツール追記。
- persona.txt: 【記憶と気遣い】節の新設ほか。web.py: 判断ログの日本語名追加。
- core.py: `_finish` に「ツール実行後にモデルが無言（…）なら直近のツール結果を返答に使う」保険を追加
  （remember 実行後に返答が（…）になる穴を実機で発見・修正。既存の『音消して』等の無言にも効く）。
- scripts/scenario_test.py: 記憶×予定×天気の6ケース追加（dry-run なので profile.json を汚さない）。
- 検証(2026-06-11・実機): ①「明日の予定なんだっけ？」→ツール無しで「明日（6/12金）は19時から塾ですよ。
  勉強、ちゃんと進めてます？^^;」。②「大学明日雨大丈夫かな」→ get_weather(茨木) 実行、明日の実予報
  （朝18%→昼晴れ）と塾19時を融合して「傘要らなさそう」まで言い切り。③「覚えておいて」→ remember 保存→
  別ターンで参照成功→ forget で対象だけ削除（「あやさんの誕生日」を消しても「彼女はあやさん」は残る）。
  ④場所未指定「天気どう？」→ 既定地（茨木）で回答。
  途中、ツール無しで「忘れました」と言う捏造を1回観測 → persona に「保存・削除は必ずツール実行後に報告」を
  明記して再検証で解消（ただし LLM 確率挙動なので完全保証ではない）。
- 制約・残る穴:
  - 単一ユーザー前提・平文JSON（暗号化なし）。Mac ローカルに置く前提。
  - `forget` は部分一致なので短すぎる query だと巻き添えの可能性（消した内容を返して気付けるようにはした）。
  - facts が増え続けると注入トークンが膨らむ（要約・整理は将来課題）。
  - wttr.in の日本語訳が欠ける時間帯は英語表記が混ざる（LLM が訳すので実害小）。
  - 予定の「過去分の掃除」（終わった dated の削除）は未実装。
