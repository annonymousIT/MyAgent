# ADR-0039 月額コストのハード上限 — core に集約して全入口で止める

- 状態: 採用（2026-06-11）。[ADR-0033](0033-cost-meter-and-cache-threshold.md)（コストメーター）の実効化。

## 課題
ADR-0033 のコストメーターは**記録・表示するだけ**で、超過しても止まらなかった。さらに記録は `web.py`
だけにあり、`agent.py`（旧・独自ループ）と `voice.py` 経由は台帳から漏れていた。テスト段階での浪費や
暴走課金を防ぐ実効的なブレーキが無い。目標は**月300円以下を死守**（TeaMy のコスト美学の横展開）。

## 判断
- **台帳と上限を `core.py` に集約**：`costs.jsonl` への記録・月集計・予算判定を一本化。`run_turn` が必ず通る。
- **ハード上限ゲート**：ターン頭で当月実測が `MYAGENT_MONTHLY_BUDGET_YEN`（既定300）以上なら
  **API を一切呼ばず**人格で打ち切る（実測 calls=0 / ¥0）。`dry_run` は課金されないので通す。
- **80%で警告色**（warn）。UI（web/agent）は今月¥/残額/ペースを表示。
- **`agent.py` を core.run_turn の薄いUIに作り替え**（旧版は予算/キャッシュ/捏造ガードを素通りしていた）。
- **`setup.py` 再課金ガード**：`config.auto.json` があれば再分類しない（`--force` のみ）。

## 影響
- `core.py`: `month_spent` / `budget_status` / `_log_cost` / ゲート。`web.py`: 二重記録を廃止。`setup.py`: ガード。
- 実測（2026-06-11・dry_run）: 温キャッシュ ≈¥0.2/ターン、冷キャッシュ初手 ≈¥1。普通の利用で月¥110〜220 見込み。
  超過時ゲートは API 呼び出し0・¥0 を確認。
