# ADR-0043 高速パス — 頻出コマンドをコードで判定し LLM を介さず即実行

- 状態: 採用（2026-06-12）。[ADR-0042](0042-per-turn-cost-rephrase-ttl.md)（1ターン単価分析）の構造的下限を破る本命。

## 課題
実機テストで3つの痛みが同時に顕在化：
1. **レイテンシ**「声が聞こえるまでおっそい」。ツール操作のたびに Haiku を2〜3往復し、初手は冷キャッシュ書込待ちも乗る → 発声まで3〜5秒。
2. **コスト** ツールターン ¥0.5超が構造的下限（ADR-0042）。
3. **Haikuレート制限** 24時間で213回超過しサービス劣化。
共通の根っこは**「単純なコマンドにも LLM を毎回通している」**こと。「電卓開いて」は意図も対象解決もコードでできる＝LLM の出番ではない。

## 判断
- **高速パス `fastpath.py` を新設**。末尾動詞＋既存リゾルバで意図を判定し、LLM 0回・即時・¥0 で実行：起動 / 閉じる / しまう / 出す（最小化中は復元・未起動は起動を自動判別）/ 音量。
- **汎用性は失わない＝“追い越し車線”であって置換ではない**。少しでも曖昧（質問・状態確認「〜てる？」・複合「A閉じてB出して」・対象が解決しない間接表現「友達と通話する」・配置系）なら `match` が **None を返し通常の LLM パス（core.run_turn）へ落ちる**。失う能力はゼロ、足すのは無料の速い車線だけ。
- **誤爆より「LLMで2-3秒待つ」を選ぶ**思想。`_BAIL`（質問語・状態確認語）と複合検出と「対象が既存アプリとして解決するか（`_app_matches`）」の3ガードで、怪しければ即退避。
- **嘘報告をしない・ロボ口調を漏らさない**：`run` の結果を `succeeded()` で判定し、**成功時のみつむぎ相槌**（起動時プリ合成・人格を保ったまま¥0）。**失敗時は LLM 向けの生メッセージを喋らず通常の LLM パスへフォールスルー**（文脈と人格で適切に処理。失敗＝何も起きていないので二重実行にならない）。[ADR-0041] の「命令送った≠効いた」と一貫。
- **対象名の正準化**（実機で判明）：別名（「スポティファイ」）で引くと窓タイトル「Spotify Premium」を探せなかった（`_resolve_entry` は値だけ返し正準名キーを落とす）。`_resolve_name` を新設し**正準名（英名）を窓タイトル候補に追加**。`run_system` も日本語キーに加え正準アクション名（`volume_up`）を受けるよう堅牢化。
- **テスト容易性**：`match(text)` は副作用なし（Windows API も叩かない）＝オフラインで routing と誤爆ガードを全数検証（selftest 20+ケース）。状態依存（復元 vs 起動）は `run` 側に寄せた。

## 影響
- `fastpath.py` 新規（match/run/succeeded）。`voice.py`：STT後・LLM前に高速パス分岐＋相槌プリ合成。`selftest.py`：意図ルーティング＋誤爆ガード（101 PASS）。
- 想定効果：起動/閉じる/しまう/出す/音量が **声まで0.5秒前後・LLM 0回・¥0**。これらが全体の相当割合なら平均単価・レート制限消費・体感速度が同時に改善。雑談・データ取得・間接意図・配置は従来どおり LLM。
- 残し：配置系（左/右/モニタ）は曖昧度が高く LLM の柔軟性が活きるため v1 では高速パスに載せない。タブ全把握（ADR-0041残課題）も別途。
