# ADR-0015 ブラウザの開き方（既定・新規タブ・通常プロファイル）

- 状態: 採用（2026-06-11）

## 課題
`open_site` でサイトを開くとき、どのブラウザ／タブかウィンドウか／どのプロファイルで開くかを決める必要がある。ログイン維持とタブの散らかり防止を考慮したい。

## 論点と選択肢
- ブラウザ：OS既定 / 指定（Chrome等）
- 開き方：新規タブ / 新規ウィンドウ / 既存タブ再利用（dedupe）
- プロファイル：通常 / シークレット
- タブグループへの自動振り分け：する / しない

## 判断
- **既定ブラウザ・通常プロファイル・新規タブ**で開く。
- 新規ウィンドウは使わない。シークレットは使わない。
- **タブグループへの自動振り分けは保留**（[#17](../issues_plan.md) で将来検討）。
- 重複タブ回避（dedupe）も一旦見送り、まずは新規タブ。

## 理由
- ログイン状態（Cookie/セッション）は**プロファイル単位**で保持される。既定ブラウザの通常プロファイルで開けば、タブ／ウィンドウのどちらでもログインは維持される。「新規ウィンドウだと認証が切れる」は誤解で、切れるのはシークレット／別プロファイルのときだけ。
- タブグループ自動振り分けは Chrome の AppleScript がタブグループ非対応で、Chrome 拡張が必要 → コスト過大なので今はやらない（"作らない判断"）。

## 影響
- 現状の `webbrowser.open(url)`（既定ブラウザ・新規タブ・通常プロファイル）を踏襲。
- タブグループ振り分け・dedupe は将来 issue（保留）。
- 名前がサイトとPWAアプリで衝突する場合の優先は [ADR-0016](0016-site-vs-pwa-app.md) を参照。
