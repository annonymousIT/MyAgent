# ADR-0028 起動中アプリの把握＋捏造防止（やってない操作を報告しない）

- 状態: 採用（2026-06-11）。実機で発覚した「状態を見ずに推測で配置した」バグの根治。[#20] の軽量先行実装。

## 課題
「通話しながらYouTube見たい」で、YouTube だけ起動・配置したのに「Discordも左に並べました」と
**やっていない配置を報告**した（捏造）。原因はエージェントが**いま何が起動しているかを一切見ておらず**、
会話履歴だけで状態を推測していたこと。ユーザ自身が「起動アプリの把握ができていない」と正しく診断。

## 判断
1. **起動中アプリをシステムプロンプトに毎ターン注入**（`tools.running_apps()`）。これを現在の実状態の基準にする。
   - 取得は System Events のプロセス名一覧（1回・約0.45s）からノイズ（システムUI・開発ツール・自分）を除く方式。
   - **制約: Chrome PWA は実体が "app_mode_loader" に潰れて個別判別できない**ため一覧に出ない
     （window タイトル走査は約6.6s と遅く不安定なので不採用）。PWAの開閉確実性は下記②で担保。
2. **捏造防止の明文化（persona）**: 実際に実行した操作（ツール結果）だけを報告。やっていない起動/配置を
   「並べました」と言わない。失敗は正直に伝える。複数アプリを並べる時、必要なアプリが起動中一覧に無ければ
   先に launch_app（idempotent＝開いていれば前面化）してから配置する。
3. **ツール側の自己修復**: `manage_window` は配置失敗（ウィンドウ無し）時、対象アプリを起動して一度だけ
   並べ直す。モデルが launch を飛ばしても、PWA未起動でも、最終的に並ぶ（2層防御）。

## 影響
- tools.py: `running_apps()` 追加（軽量・ノイズ除去）。`manage_window` に起動→再試行のフォールバック（`_relaunched`）。
- core.py: `available_operations()` に「いま起動中のアプリ」を注入。
- persona.txt: 状態に基づく判断＋捏造防止＋（PWA含む）配置前 launch を明記。
- 検証(2026-06-11): 「いま何開いてる？」→注入一覧を正しく回答。「Discord左、YouTube右で並べて」(YouTube閉)→
  launch×2＋manage_window×2 を実行、捏造なしで実配置（YouTube は自動起動経由）。
- 残: リソース使用率（CPU/RAM）読み取りは [#20] の本体スコープとして未着手。
