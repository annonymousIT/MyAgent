# ADR-0010 設計判断の記録方式（ADR正本＋Issue窓口）

- 状態: 採用（2026-06-11）

## 課題
設計変更を二人で承認しても、判断の経緯（なぜそうしたか）が会話に流れて消える。後から「課題→判断→理由」を引けないと、改善の一貫したストーリーが残らない。

## 選択肢
- A. リポジトリ内 ADR ファイルのみ
- B. GitHub Issue のみ
- C. 両方（ADR=正本＋Issue=窓口）

## 判断
**C**。`docs/adr/*.md` を正本として git 履歴に残し、GitHub Issue を議論・可視化の窓口としてミラーする。承認したものだけ記録する。

## 理由
- ファイルは**オフラインでも履歴でも確実に残る**（gh 未導入でも今すぐ書ける）。
- Issue は一覧性・議論・ラベル運用に向く。
- 両取りで互いの弱点（ファイル=議論しにくい / Issue=消える・検索性）を相殺。

## 影響
- 運用フロー：提案 → 二人承認 → ADR 追加 →（`gh` 導入後）`scripts/create_issues.sh` で Issue 作成。
- 当面は `gh` 未導入のため **ADR 先行・Issue は後追い**。
