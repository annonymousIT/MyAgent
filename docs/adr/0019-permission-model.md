# ADR-0019 権限・能力モデル（可逆性ベースの3段階）

- 状態: 採用（2026-06-11）

## 課題
エージェントにどこまでの権限を与えるか。何でも実行は危険、限定しすぎると使えない。境界を「登録 vs 未登録」ではなく**影響の可逆性**で引く。

## 判断（Green / Yellow / Red）
- 🟢 **Green（無確認で実行）**：URL/検索を開く、**インストール済みアプリの起動（全アプリ）**、安全なシステム操作（音量/輝度/モニタ）、公開Webの読み取り。
- 🟡 **Yellow（実行するが要注意）**：個人/ローカル情報の**読み取り**（カレンダー/ToDo）。読み取り専用・LLMが本人分を選別・**外部送信なし**（[ADR-0009](../issues_plan.md)）。ファイル読み取りは当面スコープ外。
- 🔴 **Red（確認 or 禁止）**：
  - アプリの**終了/閉じる** → 実行前に確認。「保存してない作業ないですか？」と聞き、**返答を得てから中断/実行を決める**。未保存があるアプリ（Word等）はOSの保存ダイアログが挟まるので(Step3で)音声通知。
  - スリープ/再起動/ログアウト → 確認。
  - ファイル削除/移動/書込・メール送信/投稿/送金 → 確認。
  - **任意シェルコマンド実行 → 確認付きでも禁止**（LLMに汎用execツールを渡さない）。

## 確定した個別判断（ユーザー承認 2026-06-11）
- **run_system**：登録済み（安全）は無確認＋危険操作は確認。任意シェルは不可。
- **情報**：読み取り専用・LLM選別・外部送信なし。ファイルは当面スコープ外。
- **アプリ起動＝Green（無確認）／アプリ終了＝確認必須**。
- 基本方針：迷ったら**聞き返す**。

## 影響
- `launch_app` は全スキャンアプリを起動可（[ADR-0011/0012](0011-framework-two-layer-config.md) で実現済）。
- アプリ終了 `quit_app` を新設する場合は確認フロー必須。
- 情報読み取り系ツールは Yellow 規定に従う。
- アクティビティモニタ（プロセス/リソース状況）の読み取りは read 系の能力候補（feature, Issue化）。
