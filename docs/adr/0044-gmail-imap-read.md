# ADR-0044 Gmail 受信メール読み取り（IMAP・アプリパスワード・読み取り専用）＋予定の条件注入/過去取得

- 状態: 採用（2026-06-12）。[ADR-0034](0034-google-calendar-ical.md)（カレンダーiCal）と同思想。

## 課題
1. **メール（Gmail）が未連携**。当初の本丸「帰宅したら予定とメールを…」のメール側が手付かず。
2. カレンダー注入が**毎ターン ~194tok（予定込みで揮発951tok）** 乗り、コスト方針（増やさない）と緊張。
3. **過去予定が見えない**＝「昨日のデートどう？」のような能動的な気遣いができない。

## 判断
- **Gmail は iCal と同じ「OAuth不要」路線**：2段階認証→**アプリパスワード**を発行し `.env` に2行
  （`GMAIL_ADDRESS` / `GMAIL_APP_PASSWORD`）。`imaplib`（標準ライブラリ）で `imap.gmail.com` に接続。
  - **読み取り専用・ヘッダのみ**（差出人/件名/日時、本文は取らない＝privacy/コスト）。`readonly=True` で既読化しない。
  - **オンデマンドのツール `get_mail`**（毎ターン注入しない。メールは大きく私的なので「メール来てる？」の時だけ）。
  - 落ちない：未設定・認証失敗・接続失敗は静かに空（ツールは設定方法を返す）。新規依存なし（imaplib同梱）。
- **予定は「関連ターンだけ注入」**（コスト・[ADR-0034]改）：`_schedule_relevant(user_input)`（予定/日付/挨拶/曜日語）が
  真の時だけ Date map＋予定ブロックを載せる。**非関連ターンの揮発 951→278tok**（雑談/操作で約673tok=¥0.1節約）。
  高速パスと同じ「要る時だけ払う」。過小検知が機能欠落なので語彙は広め（過剰検知は数十tokの損のみ）。
- **過去1週間の予定を追加**：`calendar_src.past_events(7)`。`[過去1週間の予定]` ブロックで「昨日どうだった？」の材料に。
- **予定の出典分離**（前段で実装）：`[Google Calendar（正本）]` と `[口頭で覚えた予定]` を別ブロックにし、
  自分の記憶に引っ張られてカレンダーを軽視するのを防ぐ。同日同時刻はカレンダー優先で重複排除。

## セキュリティ
アプリパスワードは「メール読み取りを許す」資格情報。**.env（gitignore済）に置き、チャット/commit に絶対貼らない**。
漏れたら Google 側で当該アプリパスワードを失効させる。本文は取得しない設計で露出を最小化。

## 影響
- 新規 `mail_src.py`（IMAP）＋ `tools.get_mail` ＋ TOOL_DEFS（17本目・キャッシュ側で安価）。
- `calendar_src.past_events` / `_events_between` 追加。`profile_store.context_text(include_schedule=)` で予定ブロックをゲート＋過去追加。
- `core`：`_schedule_relevant` ＋ `build_system_prompt(persona, user_input)` で揮発側にのみ判定を通す（安定ブロックは不変＝キャッシュ維持）。
- 検証: 未設定でも全経路が落ちない（selftest 104 PASS）。実メールE2Eはアプリパスワード設定後。
