# Issue 計画（設計判断の記録 = ガクチカ素材）

> 1論点 = 1 Issue。面接で「課題→判断→理由」を即引けるようにする台帳。
> `scripts/create_issues.ps1`（Win）/ `scripts/create_issues.sh`（Mac）で一括作成できる。

| # | タイトル | 要点 |
|---|---|---|
| 1 | 操作を「汎用ツール＋設定表」に抽象化する（引き算思想） | 機能ごとにツールを増やすと発散。汎用4ツール＋対応表に集約し、拡張は表に1行 |
| 2 | OS差分は設定ファイルに隔離する（クロスプラットフォーム） | コード共通・差分はconfig_win/mac。`platform.system()`で自動切替 |
| 3 | コンテキスト管理 vs APIコスト | 全履歴は渡さず直近N＋古い記憶は要約圧縮。賢く渡す＝安く深く |
| 4 | 画面振り分けは固定ルールでは破綻する | 「動画は中央」固定は勉強+サブ動画で破綻。メイン判断をLLMに委ねる |
| 5 | 捏造防止：数字・予定は実データのみ | アクセス数・予定をでっち上げない。知らないことは言わせない |
| 6 | GUIレス（作らない判断） | 発話で体験が完結。GUIを意図的に持たない |
| 7 | 自律性の制限：自動常駐・遠隔操作の封印 | 起動時常駐と遠隔操作はスコープ外。危険操作は実行前に確認を挟む |
| 8 | 帰宅トリガーは「ただいま」手動発火 | 自動常駐は不安＝制御を握れる手動を選択。誤爆もしない |
| 9 | カレンダーは全取得→LLMが本人分を選別 | 実カレンダーは家族予定だらけ。取得は正直に全部、取捨はLLM |
