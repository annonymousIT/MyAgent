# Issue 計画（設計判断の記録 = ガクチカ素材）

> 1論点 = 1 Issue。面接で「課題→判断→理由」を即引けるようにする台帳。
> `scripts/create_issues.ps1`（Win）/ `scripts/create_issues.sh`（Mac）で一括作成できる。

| # | タイトル | 要点 |
|---|---|---|
| 1 | 操作を「汎用ツール＋設定表」に抽象化する（引き算思想） | 機能ごとにツールを増やすと発散。汎用4ツール＋対応表に集約し、拡張は表に1行 |
| 2 | OS差分は設定ファイルに隔離する（クロスプラットフォーム） | コード共通・差分はconfig_win/mac。`platform.system()`で自動切替 |
| 3 | コンテキスト管理 vs APIコスト | 全履歴は渡さず直近N＋古い記憶は要約圧縮。賢く渡す＝安く深く |
| 4 | 画面振り分けは固定ルールでは破綻する | 「動画は中央」固定は勉強+サブ動画で破綻。メイン判断をLLMに委ねる |
| 5 | 捏造防止：数字・予定は実データのみ | アクセス数・予定をでっち上げない。知らないことは言わせない |
| 6 | GUIレス（作らない判断） | 発話で体験が完結。GUIを意図的に持たない |
| 7 | 自律性の制限：自動常駐・遠隔操作の封印 | 起動時常駐と遠隔操作はスコープ外。危険操作は実行前に確認を挟む |
| 8 | 帰宅トリガーは「ただいま」手動発火 | 自動常駐は不安＝制御を握れる手動を選択。誤爆もしない |
| 9 | カレンダーは全取得→LLMが本人分を選別 | 実カレンダーは家族予定だらけ。取得は正直に全部、取捨はLLM |
| 10 | 設計判断の記録方式（ADR正本＋Issue窓口） | 承認した判断をdocs/adrに正本で残し、Issueにミラー。経緯を消さない |
| 11 | フレームワーク化：config 2層（auto/user） | 配布のため自動層＋手動層に分割。再スキャンで手動編集が消えない |
| 12 | アプリ分類・呼び名のLLM自動生成 | スキャンしたアプリをClaudeが分類＆略語生成。誤りは手動層で補正 |
| 13 | 略語・口語の解釈（menu制約＋ファジー＋聞き返し） | 頻出語は生成aliasで決定的、漏れはLLMが最近傍。不確実なら聞く |
| 14 | 言い間違い・誤認識の吸収（可逆性段階化＋エコー） | 可逆操作は即実行＋報告、危険操作は確認。ターンまたぎ訂正はStep5 |
| 15 | ブラウザの開き方（既定・新規タブ・通常プロファイル） | ログインはプロファイル単位で維持。新規タブで開く。ウィンドウ/シークレット不使用 |
| 16 | サイトとPWAアプリの衝突解決（PWA優先） | 同名がサイトとPWA両方ある時はアプリ優先。config.userで個別上書き |
| 17 | （保留）タブグループ自動振り分け／重複タブ回避 | ChromeのAppleScriptが非対応。Chrome拡張が要るため将来検討 |
| 18 | 登録外でもPC内でできる範囲で最大限応える | 3段階。Tier2でWeb検索/サイトを開く。捏造防止維持。open_url/web_search追加 |
| 19 | 権限・能力モデル（可逆性ベース3段階） | Green=起動/開く/安全操作・Yellow=個人情報読取・Red=終了/危険操作は確認、任意exec禁止 |
| 20 | （feature）アクティビティモニタ読み取り | プロセス/リソース状況を読む読み取り系ツール候補（TaskManager的なやつ） |
| 21 | 情報配信モデル＋B（開いて見せる+要約+完了時クローズ） | ephemeral=見せて伝えて自動クローズ／persistent=残す。ADR-0021 |
| 22 | （feature）Cメディア深掘り（YouTube/音楽の検索ディープリンク） | 「この動画」「あれ流して」→検索URLを開いて残す |
| 23 | （feature）A+Dウィンドウ管理（モニタ把握・サイズ・移動） | 新能力トラック。要アクセシビリティ許可。AppleScript→相性悪ければHammerspoon |

> #10以降の判断記録（正本）は [`adr/`](adr/) に置く（ADR=正本／Issue=窓口）。
